# Pera Collage Studio

Веб-приложение для создания товарных коллажей.

- `Админ` настраивает шаблоны, фирмы и сотрудников
- `Сотрудник` входит под своим пользователем и делает коллажи
- шаблоны и история хранятся в файлах
- пользователи хранятся в `SQLite`

## Локальный запуск

1. Открой PowerShell в папке проекта
2. Запусти:

```powershell
powershell -ExecutionPolicy Bypass -File .\serve.ps1
```

3. Открой:

```text
http://localhost:8080
```

Важно:

- через `http://localhost:8080` всё работает через сервер
- через `file://` тоже можно работать, но браузер попросит выбрать папку данных
- в standalone-режиме данные пишутся в реальные файлы через File System Access API, а не в `localStorage`

## Где теперь хранятся данные

### Пользователи

Пользователи больше не хранятся в браузере и не должны жить в шаблоне.

Они лежат в SQLite базе:

- `pera.sqlite3`

Путь по умолчанию:

- внутри папки данных сервера

### Шаблоны

- `templates/studio-template.json`
- `templates/scenes/*.json`

### История коллажей

- `history/records/*.json`
- `history/images/*.png`

## Локальный standalone-режим

Если открыть `index.html` напрямую через `file://`, приложение может работать без сервера в Chromium-браузерах.

Как это устроено:

- браузер попросит выбрать папку данных
- шаблоны, пользователи и история будут сохраняться туда в файлы
- `localStorage` и `sessionStorage` не используются как хранилище данных

В standalone-режиме:

- пользователи сохраняются в `users.json`
- шаблон сохраняется в `templates/studio-template.json`
- сцены шаблонов — в `templates/scenes`
- история — в `history/records` и `history/images`

## Браузерное хранение

Сейчас важные данные не должны сохраняться в `localStorage` или `sessionStorage`.

То есть:

- пользователи не в браузере
- шаблоны не в браузере
- история не в браузере

После обновления страницы:

- вход сотрудника сбрасывается
- админка снова требует вход

Это нормально, потому что сессия теперь не считается источником данных.

## Облако

Проект подготовлен под деплой через Docker.

Есть:

- `Dockerfile`
- `.dockerignore`
- переменные окружения:
  - `HOST`
  - `PORT`
  - `PERA_DATA_DIR`

Для облака нужен persistent disk / volume, иначе:

- база пользователей
- шаблоны
- история

могут пропасть после рестарта.

Рекомендуемое значение:

```text
PERA_DATA_DIR=/app/data
```

## Что уже готово на сервере

Сервер умеет:

- отдавать шаблон по `/api/template`
- сохранять шаблон по `/api/template`
- отдавать пользователей по `/api/users`
- сохранять пользователей в SQLite по `/api/users`
- отдавать историю по `/api/collages`
- сохранять историю по `/api/collages`
- отвечать health-check по `/healthz`

## Обновление VPS одной командой

После того как новая версия уже отправлена в GitHub, на VPS можно обновить сайт одной командой:

```bash
bash /var/www/pera-collage-studio/update-vps.sh
```

Что делает скрипт:

- забирает свежий код из `main`
- обновляет файлы проекта на сервере
- перезапускает `pera-collage`
- показывает итоговый статус сервиса
